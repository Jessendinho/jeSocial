jeSocial — Development Roadmap

1. Purpose

This roadmap organises the development of jeSocial into manageable phases.

It provides direction while allowing priorities to change through explicit product-owner decisions.

A roadmap milestone is not proof of implementation.

2. Development principles

Development should prioritise:

- Protecting existing working functionality.
- Mobile-first user experience.
- Low-data performance.
- Security and privacy.
- Affordable infrastructure.
- Reliable functionality before unnecessary complexity.
- Testing before deployment.
- Gradual and controlled development.

3. Phase 1 — Foundation and documentation

Objectives:

- Establish the product identity and vision.
- Document product requirements.
- Establish official terminology.
- Document design principles.
- Record approved decisions.
- Record the actual project status.
- Document the proposed technical architecture.

Expected outcome:

A documented project that different AI assistants and developers can understand consistently.

Status: In progress.

4. Phase 2 — Prototype review and stabilisation

Objectives:

- Inspect the latest prototype.
- Review every existing interface.
- Test existing interactions.
- Identify bugs and inconsistencies.
- Improve mobile responsiveness.
- Preserve working functionality.
- Identify missing features.

Expected outcome:

A stable and understood frontend foundation.

Status: Proposed.

5. Phase 3 — Backend and database foundation

Objectives:

- Evaluate backend options.
- Confirm the database architecture.
- Design the database schema.
- Establish authentication.
- Define user permissions.
- Establish secure data access.
- Plan backups and recovery.

Supabase is the proposed direction, subject to approval.

Expected outcome:

A secure backend foundation capable of supporting persistent accounts and content.

Status: Proposed.

6. Phase 4 — Core social networking

Objectives:

- User registration and login.
- User profiles.
- Persistent publications.
- Approval and Disapproval.
- Responses.
- Amplifications.
- Socialize functionality.
- The Vault.
- Persistent engagement counts.

Expected outcome:

Users can create accounts and interact with persistent content.

Status: Proposed.

7. Phase 5 — Publishing and media

Objectives:

- Expand The Studio.
- Support image publications.
- Evaluate video publishing.
- Support links and external articles.
- Consider polls.
- Establish media storage.
- Implement upload validation and compression.
- Define publication editing and deletion.

Expected outcome:

A more complete publishing experience for ordinary users and professional publishers.

Status: Proposed.

8. Phase 6 — News and discovery

Objectives:

- Improve The Pulse.
- Develop The Compass.
- Support professional publishers.
- Establish reliable news-source integrations.
- Develop content categorisation.
- Evaluate feed ranking.
- Distinguish verified publishers from ordinary accounts where appropriate.

Expected outcome:

A balanced news and social discovery experience.

Status: Proposed.

9. Phase 7 — Notifications and communication

Objectives:

- Develop The Signal.
- Implement real notifications.
- Add notification preferences.
- Evaluate direct messaging.
- Consider other communication features.

Expected outcome:

Users can receive meaningful updates about activity on the platform.

Status: Proposed.

10. Phase 8 — Security, performance and PWA

Objectives:

- Conduct security reviews.
- Improve database access controls.
- Protect against abuse and spam.
- Optimise images and media delivery.
- Improve loading performance.
- Evaluate offline functionality.
- Implement PWA capabilities where justified.
- Test on different Android devices and network conditions.

Expected outcome:

A more secure, efficient and dependable platform.

Status: Proposed.

11. Phase 9 — Testing and launch preparation

Objectives:

- Conduct functional testing.
- Test account and publication workflows.
- Test mobile usability.
- Identify security weaknesses.
- Evaluate operating costs.
- Prepare monitoring and backups.
- Resolve critical bugs.
- Prepare deployment.

Expected outcome:

A launch-ready product with verified core functionality.

Status: Proposed.

12. Phase 10 — Growth and expansion

Potential future areas:

- More African languages.
- Additional publisher partnerships.
- Advanced discovery.
- Creator and publisher tools.
- Better analytics.
- International expansion.
- Additional platform integrations.

These ideas require separate evaluation and approval.

Status: Future possibilities.

13. How progress must be recorded

Every roadmap item should use one of these statuses:

- Proposed.
- Discussed.
- Approved.
- Implemented.
- Tested.
- Deployed.

Do not mark a task complete simply because its documentation has been written.

14. Roadmap change control

The product owner determines priorities and approves major changes.

AI assistants and developers may recommend a different sequence when technical evidence justifies it.

Any significant change must be explained and documented before implementation.

15. Final principle

Build jeSocial deliberately.

Protect the foundation, prioritise real user needs, manage costs and develop a reliable product before pursuing unnecessary complexity.

The objective is not simply to build another social media application. It is to build a sustainable Africa-first news and social platform with global potential.
