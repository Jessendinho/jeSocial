jeSocial — Design System

1. Purpose

This document defines the visual identity and user experience principles of jeSocial.

All interface development should follow these guidelines unless the product owner approves a change.

2. Brand identity

jeSocial should feel:

- Modern and professional.
- African-first, globally relevant.
- Trustworthy and welcoming.
- Bold but not visually overwhelming.
- Simple, accessible and efficient.

The design must not look like a direct copy of another social platform.

3. Official colour palette

Colour| Hex code| Purpose
Forest Green| #123B2C| Primary brand colour
Gold| #E8B84B| Accent and highlights
Cream| #F4F2EA| Main light background
Dark Ink| #17251E| Main text and dark surfaces
Red| To be defined| Disapproval and destructive actions

Use forest green and gold as the central brand colours.

Red must not become a general brand colour. Reserve it for negative or destructive states.

4. Typography

Typography should be:

- Clear and readable on small screens.
- Consistent across all pages.
- Comfortable for long-form news and articles.
- Visually distinct between headings, body text and metadata.

Avoid excessively small text and decorative fonts that reduce readability.

The final font family is not yet approved.

5. Layout and navigation

jeSocial has five primary navigation destinations:

1. The Pulse
2. The Compass
3. The Studio
4. The Signal
5. My Space

The navigation must remain clear and consistent.

The Vault is accessible through My Space and relevant publication actions. It is not a sixth primary navigation destination.

6. Mobile-first experience

Mobile is a primary design priority.

Requirements:

- Responsive layouts.
- Touch-friendly buttons and controls.
- Readable text without unnecessary zooming.
- Minimal horizontal scrolling.
- Efficient use of screen space.
- Fast interaction and minimal loading.
- Low-data usage.

Desktop layouts should adapt without compromising the mobile experience.

7. Publication design

Every publication should make it easy to identify:

- Author or publisher.
- Profile image or source identity.
- Publication time.
- Main content.
- Category where applicable.
- Approval and Disapproval counts.
- Response and Amplification counts.
- Available actions.

Images and videos should fit the interface without unwanted cropping.

Long articles should remain comfortable to read.

8. Interaction states

Interactive elements must communicate their current state.

Examples:

- Approval: clearly indicate when active.
- Disapproval: clearly indicate when active.
- Response: open the relevant discussion.
- Amplify: communicate successful sharing.
- Vault: indicate whether a publication is saved.
- Socialize: distinguish between connected and unconnected states.

Do not rely on colour alone to communicate meaning.

9. Themes

Light mode: Current prototype's default theme.

Dark mode: Desired future capability; not yet implemented.

Dark mode should preserve readability, contrast and the official brand identity.

10. Accessibility

The interface should aim for:

- Strong text/background contrast.
- Readable font sizes.
- Clear labels for controls.
- Keyboard accessibility where applicable.
- Visible interaction states.
- Meaningful alternative text for important images.
- Clear error and success messages.

11. Performance and data efficiency

The design should support users with limited connectivity and affordable devices.

Priorities:

- Optimised images and videos.
- Avoid unnecessary animations.
- Avoid heavy interface dependencies.
- Load essential content efficiently.
- Provide useful feedback during loading and errors.

12. Current implementation status

The existing prototype uses:

- Forest green, gold, cream and dark ink.
- A responsive layout.
- Desktop navigation and mobile bottom navigation.
- A light visual theme.

Dark mode, full accessibility validation and production-level performance optimisation remain unfinished.

13. Change control

This document is the design reference, not permission to redesign the product.

Any major change to colours, navigation, layout or visual identity requires product-owner approval.

Preserve working interface behaviour when making design changes.
